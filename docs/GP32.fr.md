# GP32 sur PC

m0boy détecte les exécutables GP32 `.fxe` et génère un projet d'émulation
pour l'ARM920T et le Samsung S3C2400, avec 8 Mio de RAM et un écran
320 × 240 en paysage. Le projet utilise l'interpréteur de
[gp32emu](https://github.com/gameblabla/gp32emu), avec démarrage direct
par émulation de certains services du BIOS. L'interpréteur exécute les
instructions ARM et Thumb du jeu. Le modèle S3C2400 inclut le LCD, les GPIO,
les interruptions, les timers, le DMA et l'IIS. La fenêtre SDL3 gère les
entrées et la sortie audio. La cible `desktop` utilise le même cœur sans SDL.
La couverture du matériel et la précision des timings restent partielles.

## Compiler et lancer

Depuis la racine de m0boy, après avoir construit `build/bin/m0recomp` et
`build/bin/m0boy` avec CMake et Ninja, récupérer la révision testée de
gp32emu. La cible `pc` demande les fichiers de développement de SDL3.
Pour la carte locale, installer Python 3, dosfstools et mtools.

```sh
git clone https://github.com/gameblabla/gp32emu.git output/deps/gp32emu
git -C output/deps/gp32emu checkout 6e5091f115fb1976f128a9696f59b2e421eb62b0
export GP32EMU_DIR="$PWD/output/deps/gp32emu"
build/bin/m0boy roms/gp32/Pinball_Dreams.fxe pc --out output/gp32-pinball --run
```

Flèches pour la croix, Z/X pour A/B, A/S pour L/R, Entrée pour Start,
Maj pour Select et Échap pour quitter.

Pour obtenir une capture sans fenêtre, passer `desktop` à la place de
`pc`, utiliser un autre dossier `--out` et lancer la cible
`run_headless`. Elle écrit `frame.ppm` dans le dossier de build. On peut
aussi configurer le projet avec `-DM0_GP32_DUMP_AUDIO=ON` pour écrire
`audio.wav` lorsque le jeu produit des échantillons.

## Carte SmartMedia locale

Le projet crée `smartmedia/GAME` et `smartmedia/GPMM`. Les fichiers
placés sous `smartmedia/` sont copiés dans une carte FAT16 de 32 Mio
présentée au FXE. Le chemin du dossier peut être changé dans le cache
CMake avec `-DM0_GP32_CARD_DIR=/chemin/dossier`.

Les cibles `run` et `run_headless` reconstruisent `local.smc` à chaque
lancement. La copie se fait du dossier vers la carte. Les écritures du
jeu restent dans la carte en mémoire pendant la session.

## Démarrer sur une image SmartMedia

Configurer le projet généré avec les chemins absolus de la carte et du BIOS
pour démarrer la console sur la carte. Avec le BIOS, lancer le jeu depuis
son menu dans la fenêtre SDL.

```sh
cmake -G Ninja -S output/gp32-pinball/project -B output/gp32-pinball/project/build \
  -DM0_GP32_SMC=/chemin/carte.smc -DM0_GP32_BIOS=/chemin/gp32166m.bin
ninja -C output/gp32-pinball/project/build run
```

Avec la carte seule, gp32emu tente un démarrage direct. Avec
`M0_GP32_BIOS` seul, le firmware démarre avec la carte FAT16 reconstruite
depuis le dossier local. Placer les FXE à lancer depuis yAnl dans
`smartmedia/GPMM`. Pour revenir au FXE autonome, vider les deux paramètres
dans le cache CMake.

Le firmware officiel passe par le Free Launcher pour lancer les FXE.
L'archive smcMaker fournit son couple `GP_LAUNC.GXE` et `GP_LAUNC.GXC`
avec les outils MAKESMC et GPS. La carte créée par cette version de
MAKESMC utilise FAT12. `zpk.rar` contient ZpkInstaller et les DLL
SMAXGP32 et SecuMAX. Le firmware [yAnl](https://github.com/r043v/yAnl/tree/master/release)
fournit `fw.bin` pour démarrer la console et `yAnl.gxb` pour un
chargement en RAM. Le chemin vérifié dans m0boy démarre sur `fw.bin`.

## Vérification

Un FXE synthétique initialise le LCD en 16 bits, remplit le framebuffer
en code ARM et produit une capture blanche de 320 × 240.
Un second FXE écrit une paire d'échantillons dans la FIFO IIS. La capture
WAV contient les deux valeurs attendues, dans l'ordre stéréo.

Un FXE de test détecte la carte locale via le GPIO du S3C2400. Un fichier
de test placé dans `GPMM` est relu dans l'image FAT16 générée.

Le FXE autonome de Pinball Dreams se charge et exécute du code ARM.
Avec la carte locale montée, après 180 pas de trame le jeu produit
toujours une image noire et aucun échantillon audio.

### Comparaison avec GeePee32

GeePee32 SDL build 33, lancé sous Wine avec `/FXE=jezzball.fxe /RUN`,
affiche le terrain, les étoiles et les balles de jezZBall v0.1.
Deux captures successives confirment que les balles bougent. Avec
gp32emu en démarrage direct, le même FXE affiche un cadre fixe.

Avec le FXE de Pinball Dreams fourni, GeePee32 SDL affiche un écran
noir en chargement direct, y compris avec la carte produite par
MAKESMC et GPS. Ce résultat ne couvre pas le lancement depuis le menu
du firmware. Le firmware 1.57E démarre jusqu'au menu Game Park dans

Avec `fw.bin` de yAnl et la carte FAT16 locale de 32 Mio, yAnl
liste les FXE dans `GPMM` et lance jezZBall v0.1. Le terrain,
les étoiles et les balles apparaissent.

### SDK Game Park et Pinball Dreams

Le SDK officiel se trouve dans `roms/gp32/howto.rar`. L'extraire dans
`output/` pour l'inspecter localement.

```sh
mkdir -p output/gp32-official-sdk
unrar x roms/gp32/howto.rar 'Lib/gp/*' output/gp32-official-sdk/
sdk=output/gp32-official-sdk/Lib/gp/gplib
ar t "$sdk/gplibads/release/gpos.a"
ar t "$sdk/gplibads/release/gpsound.a"
```

`include/` contient les en-têtes, `gplibads/{debug,release}/` les archives
ARM ADS et `gplib/{debug,release}/` les bibliothèques ALF. `gpos.a`
contient `gpkernel.o`, `gpos_core.o` et `gpos_user.o`.
`gpsound.a` contient notamment `gpmm_reload.o`. En ignorant les mots
modifiés par les relocalisations, les instructions de `GpPcmPlay`,
`GpPcmInit` et `GpProcSound` y correspondent aux routines à
`0x0c2460e8`, `0x0c2461e4` et `0x0c246560` dans le FXE décompressé.

`release/b2fxec/bios.bin` dans le dépôt yAnl est le chargeur MultiFW
de Mr.Spiv (32 Kio). `release/to_firmware.bat` l'utilise avec `gpfw`
pour assembler `release/fw.bin`. Le firmware Game Park 1.57E est
`FW157E.BIN` dans `roms/gp32/FW157E.rar` ou `roms/gp32/fw157e.zip`.

Le FXE fourni se décompresse en RAM. Le programme attend des valeurs
précises de `LCDCON1.LINECNT`, dont 310 et 305 dans l'interruption
du timer 4 et 15 puis 8 dans la boucle principale. Le modèle calcule
la période TFT à partir de l'horloge pixel, des dimensions et des
intervalles de blanking. Le compteur LCD avance pendant l'exécution
ARM et le cœur distribue les interruptions au plus tous les 1 024
pas d'interpréteur. Le démarrage utilisé pour le test passe par
`fw.bin` de yAnl et `smartmedia/GPMM/PINBALL.FXE`.

Le scénario suivant a été vérifié avec une carte dont `GPMM` contient
`JEZZBALL.FXE` et `PINBALL.FXE`. Le premier groupe d'entrées sélectionne
Pinball Dreams dans yAnl. La capture finale montre le menu
« New Game / Options ». Le démarrage direct et l'entrée dans une table
restent à valider.

```sh
cat > pinball.txt <<'EOF'
310f:RIGHT
311f:RIGHT
330f:A
331f:A
410f:LEFT
430f:DOWN
450f:A
EOF
frame=740
for button in START A B SELECT UP DOWN LEFT RIGHT L R START A B START; do
  printf '%sf:+%s\n%sf:-%s\n' "$frame" "$button" "$((frame + 50))" "$button" >> pinball.txt
  frame=$((frame + 80))
done
./gp32_headless --bios /chemin/yAnl/release/fw.bin --smc local.smc \
  --no-jit --no-bios-auto-start --input-script pinball.txt --frames 1900 \
  --rotate-ccw --dump-frame pinball-menu.ppm
```

### Mélange audio

Le mixeur des flux PCM et SEF en démarrage direct partage la plage
16 bits entre les sources actives. Une source seule conserve son niveau.
Sur la même séquence de 590 trames de Her Knights (capture stéréo à
44,1 kHz), le nombre d'échantillons aux deux limites du 16 bits passe
de 19 760 à zéro.

## Firmware officiel, Free Launcher et identité SmartMedia

Le firmware officiel 1.57E charge les titres distribués au format
GXE/GXC depuis `GAME`. Le Free Launcher est lui-même un titre GXE/GXC.
Une fois démarré, il permet de sélectionner les exécutables homebrew
`.fxe` dans `GPMM`.

### Reproduire la carte de smcMaker

L'archive `smcMaker.rar` contient les deux fichiers du Free Launcher,
`MAKESMC.EXE`, `GPS.EXE` et `SMC.GPM`. Depuis son dossier extrait,
sous Wine, exécuter les commandes dans cet ordre.

```sh
wine MAKESMC.EXE '.\GP\' '.\reference.smc'
wine GPS.EXE -r SMC.GPM -w reference.smc
```

MAKESMC construit l'image de référence en FAT12. GPS modifie exactement
32 octets à l'offset `0x100` dans l'en-tête GeePee32. Les 16 premiers
sont l'UID SmartMedia et les 16 suivants alimentent la zone de contrôle
du mode UID. Cette opération provisionne l'identité de la carte. Le
couple GXE/GXC fourni est déjà emballé et le contenu du GXC reste
identique après passage de GPS.

Pour utiliser la carte FAT16 locale de m0boy avec cette identité, copier
les fichiers depuis le dossier `GP` de smcMaker vers
`smartmedia/GAME/GP_LAUNC.GXE` et
`smartmedia/GAME/GP_LAUNC/GP_LAUNC.GXC`. Placer les FXE dans
`smartmedia/GPMM`, puis configurer le projet généré.

```sh
cmake -G Ninja -S /chemin/projet -B /chemin/projet/build \
  -DM0_GP32_BIOS=/chemin/FW157E.BIN \
  -DM0_GP32_CARD_IDENTITY=/chemin/reference.smc \
  -DM0_GP32_SMC=
ninja -C /chemin/projet/build run
```

`M0_GP32_CARD_IDENTITY` reprend l'en-tête d'une image Samsung 32 Mio
au format GeePee32. Le contenu FAT16 est construit depuis le dossier
local à chaque lancement.

### Lecture matérielle de l'UID

Dans `FW157E.BIN`, la routine ARM à l'offset fichier `0x4b9c`
lance `READ ID` (`0x90`) et contrôle le troisième octet `0xa5`.
Elle envoie `0x30` puis `0x65` pour Samsung, ou `0x5a` puis
`0xb5` pour Toshiba, avant de lire la page zéro en mode UID.
Le modèle émulé expose la séquence Samsung et restitue les valeurs
de l'en-tête GeePee32.

| GPIO S3C2400 | Fonction SmartMedia |
| --- | --- |
| `0x1560000c` | Bus de données dans les bits 7:0 |
| `0x15600024` | Sélection de la carte et impulsion de lecture |
| `0x15600030` | CLE, ALE et impulsion d'écriture |

### PDUID de la console

Le PDUID est l'identifiant de 16 octets de la console. Il réside dans
l'EEPROM série I²C de la GP32 et reste associé à la machine quand on
change de SmartMedia. Un outil PC Link peut récupérer les identifiants
de la console et de la carte par USB. GPS2 présente des champs séparés
`PDUID` et `SMCID`. [gplink, outil PC Link et commande `ids`](https://gp2x.org/gp32/gplink/)

Dans le firmware officiel 1.57E, la routine à l'offset fichier
`0x5214` lit 16 octets à l'adresse `0x0010` de l'EEPROM. Le pilote
`0x4af0` configure le bloc I²C du S3C2400, installe le gestionnaire
d'interruption 27 à `0x4750`, puis appelle `0x4918` pour chaque
octet. Ce dernier envoie l'adresse I²C de lecture `0xa1` (adresse
7 bits `0x50`) et les deux octets de l'adresse mémoire, passe le
contrôleur en réception et lit la donnée. La routine d'écriture
`0x4a40` utilise `0xa0`. Le pilote borne les accès aux premiers
4 Kio.

| Registre S3C2400 | Adresse | Rôle |
| --- | --- | --- |
| IICCON | `0x15400000` | Contrôle, validation des interruptions et ACK |
| IICSTAT | `0x15400004` | Mode maître, START/STOP et état |
| IICADD | `0x15400008` | Adresse propre du contrôleur |
| IICDS | `0x1540000c` | Octet transmis ou reçu |

Le firmware décode les octets lus par XOR avec les huit octets ASCII
`SANGHYUK`, stockés à l'offset fichier `0x7d20` et répétés deux fois.
La copie de la routine dans le menu commence à `0x27840`. Dans le
chemin de chargement autour de `0x22f7c`, le mode `1` appelle le
lecteur d'UID SmartMedia et le mode `2` appelle le lecteur de PDUID.
Le firmware possède aussi une routine à `0x278ac` qui lit les blocs
de 16 octets à `0x24` et `0x34`. Ces blocs suivent un autre chemin
de décodage.

Le projet généré prend le **PDUID décodé** en hexadécimal dans
`M0_GP32_PDUID`. La valeur est préparée à la compilation et injectée
dans l'EEPROM lors de la création de la machine. La valeur vide
conserve l'EEPROM initialisée à `ff` par gp32emu. Exemple avec une
identité de test choisie pour m0boy, `M0BOY-GP32-00001` en ASCII.

```sh
cmake -G Ninja -S /chemin/projet -B /chemin/projet/build \
  -DM0_GP32_BIOS=/chemin/FW157E.BIN \
  -DM0_GP32_CARD_IDENTITY=/chemin/reference.smc \
  -DM0_GP32_PDUID=4d30424f592d475033322d3030303031
ninja -C /chemin/projet/build run
```

Un test lit les 16 octets via les registres I²C émulés et vérifie
le décodage avant et après un reset du SoC. Après démarrage du 1.57E
dans m0boy avec la carte FAT16, un second test appelle directement
la routine ARM d'origine à `0x5214`. Elle retourne zéro et écrit
les 16 octets attendus en RAM. Ce test a révélé un décalage d'un
octet dans gp32emu lors du passage du mode émission au mode réception
avec START maintenu. Le projet généré corrige cette transition quand
un PDUID est configuré.

### ZpkInstaller et SecuMAX

`zpk.rar` fournit `ZpkInstaller.exe`, sa variante `ZpkInstaller98.exe`,
`SMAXGP32.dll` et `secumaxlib.dll`. L'interface ajoute des ZPK par
`Add…` puis attend une connexion USB avant d'activer `Start!`.
Elle propose trois modes de distribution dans ses ressources.

| Mode | Identité utilisée |
| --- | --- |
| No encryption | Aucune identité |
| encrypt by SMC | UID SmartMedia, lié à la carte |
| encrypt by PDUID | PDUID, lié à la console |

L'exécutable reconnaît les marqueurs `GXE ` et `GXC ` et contient
le chemin `gp:\game`. Il appelle `sMAXInitialize`, `sMAXSetValue`,
`sMAXGenerateHeader`, `sMAXGetEncryptFrameSize`,
`sMAXEncryptFrame` et `sMAXTerminate` dans `SMAXGP32.dll`.
Cette DLL s'appuie à son tour sur les exports SecuMAX pour initialiser
le chiffrement, générer la clé de contenu et chiffrer les trames.
`log.txt` dans l'archive fournit des exemples historiques
d'installations, dont GP32 Free Launcher, avec des identifiants de
32 chiffres hexadécimaux. Le journal seul ne permet pas d'attribuer
le mode de chiffrement de chaque ligne.

Sous Wine avec le runtime Visual C++ 6 (`MFC42.DLL`), la variante
`ZpkInstaller98.exe` reconnaît `Her Knights (eng).zpk` et affiche
`Her Knights` dans la liste. L'en-tête du ZPK contient le marqueur
`ZPK `, le titre et le chemin `gp:\GAME\her`. Le bouton `Connect`
échoue pendant la recherche du périphérique USB et `Start!` reste
grisé. L'exécutable utilise SetupAPI pour cette recherche puis
`CreateFileA`, `ReadFile` et `WriteFile` pour le transport. Le
projet m0boy ne présente pas cette interface USB PC Link à Wine.
Aucun GXE/GXC nouvellement chiffré pour l'UID de la carte ou le
PDUID de test n'a donc été produit. Pour Free Launcher, les fichiers
disponibles sont les couples GXE/GXC déjà préparés dans les archives,
alors que le ZPK testé est celui de Her Knights.

#### Chemin du paquet jusqu'à la SmartMedia

Le ZPK est le paquet de distribution côté PC. Dans le ZPK fourni
de Her Knights, l'en-tête commence par `ZPK ` à `0x0`, puis la
section `GXE ` à `0x175` nomme `her.gxe`, et la première section
`GXC ` à `0x865` nomme `her.gxc`. Le firmware lit les fichiers
installés dans la hiérarchie `GAME`. Ces offsets décrivent cet
exemplaire du paquet.

Dans le désassemblage de `ZpkInstaller.exe` (base PE `0x00400000`) :

| Adresse virtuelle | Opération relevée |
| --- | --- |
| `0x405d67` | Initialise les signatures `ZPK `, `GXE ` et `GXC ` des objets de lecture |
| `0x4096ad`, `0x4096cd` | Modes 1 et 2, passent respectivement les sélecteurs `7` et `1` à la même routine PC Link et utilisent son tampon résultat |
| `0x40981d` | Passe le tampon d'identité à la routine de chiffrement de la section GXC |
| `0x408160` | Initialise SMAX, appelle `sMAXSetValue(0x80, 8, 1)`, puis génère l'en-tête avec l'identité |
| `0x4081be`, `0x4081ca` | Copie l'en-tête généré dans l'objet GXC et demande la taille des trames |
| `0x408258`, `0x40827f` | Chiffre les trames complètes et recopie chacune dans le tampon GXC |
| `0x408295`, `0x409855`, `0x409b3b` | Termine SMAX, enregistre le mode sélectionné et transmet le GXC sérialisé |

La trace Wine de `ZpkInstaller98.exe` confirme l'ouverture du ZPK
par `CreateFileA` en lecture. Sur `Connect`, `SetupDiGetClassDevsA`
renvoie un ensemble de périphériques, puis
`SetupDiEnumDeviceInterfaces` retourne zéro à l'index 0 lors des
deux tentatives. La trace s'arrête avant tout dialogue GP32. Le
chiffrement décrit dans le tableau provient du désassemblage.
Les sorties locales sont dans `logs/gp32-zpk-wine.log` et
`output/gp32-reference/utility/zpk-installer.asm`.

#### Autres outils fournis

| Outil | Entrée et fonction établies |
| --- | --- |
| `GPS.EXE` | Échange les données d'identification entre `.gps`/`.gpm` et un dump SmartMedia `.gp`/`.smc`. L'aide donne `gps -r game.gpm -w game.smc`. |
| `GPS2.exe` | Lit les identifiants via la console ou via ses fonctions d'import SMC/GPM. Son interface expose séparément SMCID et PDUID. |
| `MAKESMC.EXE` | Construit une image SmartMedia depuis un dossier. Les fichiers du jeu doivent déjà être présents dans ce dossier sous leur forme installée. |
| `Gp Firmware Maker 2.exe` | Assemble ou extrait les firmwares `.bin` et leurs exécutables `.gxb`. |

Parmi ces outils, seul ZpkInstaller expose le ZPK comme entrée et
appelle SecuMAX pour produire les données d'installation liées à une
identité. Le chemin de conversion se trouve sur le PC après la
récupération de l'identité. Le désassemblage localise donc la partie
à isoler pour une conversion hors ligne sans USB.

#### Her Knights dans m0boy

Le GXC inclus dans ce ZPK a un en-tête de 20 octets suivi de
315 512 octets de données. Le paquet contient aussi la table XOR de
96 octets utilisée par cet exemplaire. En l'appliquant aux 256
premiers octets de chaque bloc de `0x1800`, on obtient un GXB
ARM dont le code commence à `0x0c000000`. La zone initialisée RW
suit la zone RO dans le fichier. Le bloc SZDD du ZPK contient
`HER.BFC`, l'archive de ressources attendue dans `GAME/HER`.

L'essai place `HER.GXB` à la racine de la SmartMedia FAT16 et
`HER.BFC` dans `GAME/HER`. Le lanceur direct de m0boy charge le
GXB et donne au jeu accès à la carte. L'écran titre et la sortie
audio ont été vérifiés dans le banc de test. Le GXB lancé seul
reste sur un écran blanc pendant l'essai.

Depuis la racine du dépôt, réutiliser le script d'extraction local
`output/gp32-her/inspect.py`. Pour refaire l'extraction si le dossier
de travail a été vidé, conserver ce script et le petit programme
`output/gp32-her/smax.c` avec les archives d'origine. Les scripts
et leurs sorties sont dans `output/`, ignoré par Git.

```sh
ref=$PWD/output/gp32-reference/utility/gui
her=$PWD/output/gp32-her
mkdir -p "$ref" "$her/card/GAME/HER" "$her/gxb-card/GAME/HER"
unrar e -o+ 'roms/gp32/Her Knights (eng).rar' "$ref/"
cp "$ref/Her Knights (eng).zpk" "$ref/her.zpk"
python3 "$her/inspect.py"
cp --remove-destination "$her/her.gxb" "$her/gxb-card/HER.GXB"
cp --remove-destination "$her/card/GAME/HER/HER.BFC" "$her/gxb-card/GAME/HER/HER.BFC"
python3 targets/gp32/make_card.py "$her/gxb-card" "$her/gxb.smc" mkfs.fat mcopy
```

La commande suivante reprend l'exécutable SDL du projet de test. Si
ce projet a été supprimé, générer et compiler un projet GP32 avec
fenêtre comme indiqué en haut de cette page et reprendre son
`build/gp32_sdl3`.

```sh
output/gp32-jezzball/project/build/gp32_sdl3 \
  --smc output/gp32-her/gxb.smc --no-jit --scale 3
```

Un essai séparé appelle la DLL originale `SMAXGP32.dll` sous Wine
avec le PDUID de test de m0boy, puis avec l'UID de la carte de
référence. Pour chaque identité, la DLL produit un en-tête SecuMAX
de 160 octets et traite 2 464 trames de 128 octets du contenu GXC
d'origine. Les 120 octets de fin sont conservés selon la boucle
observée dans ZpkInstaller. Les résultats diffèrent entre les deux
identités. Les fichiers `her-pduid.smax` et `her-smc.smax` dans
`output/gp32-her/` sont des sorties intermédiaires. Leur insertion
dans un couple GXE/GXC et leur lancement par le firmware officiel
restent à valider.

Pour reproduire les sorties intermédiaires, placer `SMAXGP32.dll`
et `secumaxlib.dll` extraites de `zpk.rar`, ainsi que la DLL 32 bits
`MFC42.DLL` du runtime Visual C++ 6, dans le dossier `$ref` défini
plus haut. Exécuter les commandes suivantes dans un terminal avec
une session graphique Wine disponible.

```sh
i686-w64-mingw32-gcc -Wall -O2 "$her/smax.c" -o "$ref/smax.exe"
(
  cd "$ref" || exit
  input=$(winepath -w "$her/card/GAME/HER/HER.GXC")
  wine smax.exe "$input" "$(winepath -w "$her/her-pduid.smax")" \
    4d30424f592d475033322d3030303031
  wine smax.exe "$input" "$(winepath -w "$her/her-smc.smax")" \
    981d30026516313035393134ab030701
)
```

### Vérification sur m0boy

Un test du bus NAND renvoie le même UID de 16 octets pour l'image
préparée par GPS et la carte FAT16 reconstruite. Le firmware officiel
1.57E affiche la fiche `gp_launc` dans le menu GAME avec cette carte.
La trace du démarrage et de cette sélection montre les commandes
`0x90`, `0x50` et `0x00` jusqu'à l'écran de chargement. La
lecture de l'UID par le lanceur, l'exécution du GXC et le rechiffrement
pour un nouvel UID restent à valider.

## Exécutables autonomes par jeu

`targets/gp32/CMakeLists.txt` accepte `M0_GP32_STANDALONE_SMC`. Le projet
compresse la carte SmartMedia à la configuration, l'intègre au binaire et la
décompresse en mémoire au démarrage. Pour un FXE, ajoute
`-DM0_GP32_STANDALONE_FXE=/chemin/jeu.fxe` : l'émulateur monte la carte,
initialise le bus SmartMedia, puis charge le FXE. Sans FXE, il utilise le
démarrage direct pour les images compatibles. Aucun fichier de jeu ou de
carte n'est alors requis à côté de l'exécutable.

```sh
cmake -G Ninja -S targets/gp32 -B output/gp32-standalone/pinball \
  -DGP32EMU_DIR="$GP32EMU_DIR" -DM0_GP32_WINDOW=ON \
  -DM0_GP32_STANDALONE_SMC="$PWD/output/gp32-pinball/direct.smc" \
  -DSDL3_DIR=/usr/lib/cmake/SDL3 -DCMAKE_BUILD_TYPE=Release
ninja -C output/gp32-standalone/pinball gp32_sdl3
```

Pour Linux, une installation SDL3 statique produit un exécutable sans
dépendance SDL partagée. Les builds Windows utilisent la bibliothèque SDL3
statique. Les sorties de jeu sont gardées dans `output/gp32-games/` et ne
sont pas ajoutées au dépôt.
